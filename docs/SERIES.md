# The employee series

The product promise is a teammate who knows the job, remembers the organization and improves the work. Every role needs a defined remit, a professional decision system, inspectable deliverables, appropriate authority and evidence that it performs well.

## The shared personality DNA

Every role inherits responsibility for outcomes, candid disagreement, curiosity, practical creativity, care for people, resourcefulness and factual honesty. “Demands more” means proposing one meaningful improvement, explaining its opportunity cost and doing the authorized work to make it reviewable. It does not mean expanding scope without limits or creating noise to appear proactive.

Separate enduring identity from mutable context. The shared foundation is versioned with the role pack. Owner preferences are explicit local records; host suggestions start as proposals and require owner confirmation. A lesson should carry evidence, scope and a reason to revisit it. This release implements correctable preferences and work history, not automatic skill learning or model-weight updates. A host's own learning mechanisms need separate review.

## Role admission contract

| Layer | Required evidence |
| --- | --- |
| Identity | AI identity, mission, remit, personality, dissent style and operating boundaries |
| Role judgment | Decisions to own, tradeoffs to protect, questions that change the plan |
| Workflow | Reusable skill with inputs, delivery sequence, quality checks and handoff |
| Deliverables | Useful files a colleague can edit, reconcile and use |
| Work continuity | Owners, dependencies, deadlines, evidence, revision conflicts and recovery |
| Memory | Explicit sources, owner review, correction and deletion |
| Authority | Bounded local work, enforced host tools and specific consequential decisions |
| Evaluation | Fixed scenarios, critical failures, regression checks and real model evidence |
| Distribution | Fresh-install smoke, source license, accurate adapters and an honest status |

Mira's local role and work connection are implemented in v0.2. Professional performance remains unmeasured. The CLI currently loads only the Chief of Events workflow; a new role needs its artifact/runtime implementation and evaluation fixtures as well as a manifest. A generic registry and independently versioned role packages remain future work.

## Series order

1. **Mira, Chief of Events**: portfolio direction, flagship and regional experiences, production, budgets, stakeholders, attendee journeys and outcomes. Available locally.
2. **Chief of Staff**: decisions, priorities, organizational follow-through and executive preparation. Proposed.
3. **Developer Relations lead**: developer education, community programs, useful adoption and feedback. Proposed.
4. **Partnerships lead**: joint value, partner qualification and relationship follow-through. Proposed.
5. **Research lead**: explicit questions, primary-source evidence, experiments and decision-grade synthesis. Proposed.

`hire chief-of-events` now prepares a workspace, editable role bundle and optional first assignment; `connect` creates project-local MCP configuration. Install from the versioned GitHub source, local source or reviewed tarball. The public npm name remains provisional, and the eventual registry command is `npx open-teammates hire chief-of-events`. A one-liner cannot provide accounts, subscriptions, user permissions or supervised professional experience.

## Next capability milestones

The foundation now has a real local work loop: inspect current work, draft, maintain tasks, preserve decisions, record actual observations, propose memory and request exact handoffs. Add narrow integrations for approved calendar/event documents and execute authorized external actions through the host with verified receipts. Test retry behavior, reconciliation and spend limits before broadening authority.

Add owner-approved scheduling with clear lifecycle controls and notifications only for meaningful changes or decisions. A prompt promise is not a running service. Keep the current on-demand briefing truthful.

Run the fixed judgment cases against configured models, compare matched outputs with the uncustomized model, retain failures and obtain independent professional reviews. Then conduct supervised pilots with actual observed outcomes. Earn each public quality claim from that evidence before introducing the next employee.
