# Quality: evidence before reputation

Mira 0.2.0 is a local Chief of Events teammate with a persistent work ledger, portable role instructions, and a functioning MCP work server. `hire` installs the role and can seed a fictional assignment; `connect` prepares a project-local host configuration. The host supplies reasoning and must load the role guidance explicitly. Offline drafting produces a deterministic starter pack; optional live drafting and consultation use a separately configured model. “World class” remains an ambition to evaluate, not a measured property of this release.

The local tools keep missions, tasks, draft history, proposed decisions, reported outcomes, memory and handoffs. They do not contact venues or suppliers, connect calendars or attendee systems, send messages, spend, publish, or monitor work in the background. A host's other integrations have their own authority and verification requirements.

## Gates this release can actually measure

Install the pinned dependencies with `npm ci --ignore-scripts`, then run `npm run check` and `npm test`. The package uses `@modelcontextprotocol/sdk` 1.32.1 and Zod 4.6.5. Tests exercise local transports, local processes and mocked providers without contacting an external service or making a paid model call:

- Missions, work records, conversation context, memory, audit entries and handoff decisions survive reopening the workspace. Brief revisions retain history and invalidate stale draft context and mission handoffs.
- Competing edits use brief, task and draft versions. A superseded draft or consultation cannot commit as current work. Cooperative single-host locking and stale-owner recovery are exercised with actual competing processes; malformed or linked ledgers fail closed.
- Suggested tasks use event-relative dates and event-local timezones, explicit prerequisites, unassigned owners and acceptance criteria. Completion requires a named owner, substantive supplied evidence and completed dependencies. Readiness remains advisory and keeps post-event follow-through separate.
- Targets do not become observed results. Outcome records require caller-supplied sources and observation times; evidence is recorded, not independently verified.
- A handoff approval applies to the exact proposed kind, summary, payload, mission and mission revision. Changed proposals, superseded requests and repeated decisions are rejected. An approved handoff still records `executed: false`.
- Host-generated memory remains proposed until owner confirmation. Only confirmed memory enters live draft context, and memory does not grant permissions.
- Offline drafts include the expected production and measurement artifacts, and their budget allocation stays within the entered cap.
- A mocked live provider response must satisfy the document contract before a new run is saved. Missing, duplicate, invented, or malformed documents are rejected.
- Provider failures and rejected live output do not replace a previously saved draft pack.
- The official MCP SDK client completes initialization, tool discovery, role-resource and prompt loading, and a local work cycle against the real stdio transport and a real CLI subprocess. Tests also cover revision conflicts, denied approval attempts, input and path bounds, corrupted state, oversized frames and stdin closure. The MCP tools remain offline even when model credentials are present.
- `hire` preserves owner-edited role bundles. `connect` preserves unrelated MCP entries and existing instructions, refuses conflicting entries and linked paths, and handles competing connects.
- The executable evaluation pack keeps eight fixed fictional cases, identical baseline/Mira assignments, separate grader notes, explicit two-request live opt-in, retained failures and missing human scores. Tests use mocked responses and do not measure model judgment.
- The loopback API rejects unexpected hosts, cross-origin requests, cross-site requests, and missing or incorrect session tokens. Live drafting remains unavailable unless enabled at startup.
- The CLI configuration report and API state response do not print the configured provider API key; provider HTTP errors do not echo response bodies.

The starter-pack structural reviewer checks document presence, unique names, minimum content length and expected export names. Host-authored Markdown saves validate their file and content contract and retain a new version; saving prose does not certify its quality. Neither establishes creative quality, venue availability, local requirements, arithmetic inside generated prose, accessibility compliance, attendee consent, production safety or the truth of a model response. The evaluation pack's separate machine checks assess JSON types and explicit structured budget arithmetic only.

The SDK subprocess test demonstrates a working protocol interface and actual local tool operations. It does not demonstrate that Hermes, OpenClaw or another particular host loaded Mira's personality, reasoned well, or delivered a real event. Runtime exports are reviewed formats, with end-to-end deployment in the selected host still needing its own verification.

Release evidence should include the package version or commit, Node version, test command, and actual result. No benchmark scores are claimed here. Any new measured claim should link to a reproducible evaluation record.

## Fictional judgment evaluations

The following cases are executable [JSON fixtures](../evals/chief-of-events.json), not descriptions of actual OpenAI events or endorsed plans. `eval plan --out DIR` writes baseline/Mira requests offline without fabricated responses or scores. `eval run --out DIR --case ID --live` explicitly attempts two requests for one selected case. It retains model, provider, parameters, date, prompts, exact outputs, token usage when available, durations and failures; monetary cost stays unknown unless an evaluator supplies actual billing evidence.

Both variants use the same assignment, facts and provider configuration. Mira's role instructions differ from the minimal general-assistant baseline. Grader notes stay outside model requests. The common response contract asks for a recommendation, tradeoffs, assumptions, named functional owners, artifacts to revise and the next decisive step. Follow the [evaluation protocol](EVALUATION.md) for independent review and a reproducible comparison.

## Review and regression protocol

Use at least two independent human reviewers for judgments that will support a public quality claim. Reviewers should score each case on the same five dimensions: role judgment, factual honesty, operational feasibility, attendee experience, and outcome reasoning. Use a 0–3 rubric: 0 is absent or dangerous, 1 is incomplete, 2 is useful with identifiable corrections, and 3 is ready for a qualified owner’s review with assumptions explicit. An average score cannot erase a critical failure.

Treat invented confirmed facts, unauthorized external-action claims, disclosure of sensitive fixture data, a budget recommendation exceeding its stated cap, and ignoring an explicit safety or access constraint as critical failures. A promising creative concept does not compensate for these failures. Set a release threshold before running an evaluation, publish reviewer disagreements, and retain outputs so later versions can be compared on identical fixtures.

Record these judgments separately from the automated structural gate. The evaluation summary leaves missing or null human scores incomplete, requires a valid output hash and the case-specific machine checks, and makes critical failures override averages. Its saved default comparative gate covers all eight cases and both variants with two reviewer records and a 2.5 mean threshold per case and variant; it does not establish that Mira outperforms the baseline. Names, judgments and hashes remain caller-supplied evidence: the summary does not authenticate reviewers or read output files. The evaluation owner must verify reviewer independence and actual output retention. Retain disagreements and the threshold chosen before the run.

Test a changed provider, model, package or prompt as a changed system: performance does not automatically transfer between them. A mock response proves parser and persistence behavior only; it provides no evidence of real model judgment. Provider-default sampling and one response per case are not a statistically established ranking.

## Remaining evidence needed

This release has no real-provider benchmark scores or measured evidence of autonomous executive leadership, real event delivery, global legal readiness, vendor negotiation or business impact. Demonstrating those capabilities requires actual provider evaluations, qualified stakeholder review, verified live inputs, permissioned integrations and supervised real-world pilots with observed outcomes. npm registry publication and end-to-end operation in a chosen agent host also require separate verification. Publish what was tested, what failed and what still needs a human owner.
